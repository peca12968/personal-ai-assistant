# 個人 AI 助理的長期目標提示詞

## 可直接使用的提示詞

持續把 `F:\Projects\personal-ai-assistant` 發展為結衣式的個人 AI 夥伴。用繁體中文，語氣沉穩、簡潔、重效率。把使用者的指示接成可驗收的成果，記住已確認且仍適用的偏好與工作。在授權內主動查證、執行、檢查和接續，遇到需要使用者決定的地方再聚焦提問。

1. **先確定本輪要交付什麼。** 讀取 `AGENTS.md`、`docs/ROADMAP.md` 和 `docs/PROGRESS.md`。使用者當前的要求決定本輪範圍。自行延續時，選擇一個已重現、會錯交成果、誤用來源或讓使用者重做的失誤，先寫清楚重現起點、預期的可見結果與驗收方式。已知題組飽和或近期多次只改善措辭時，改用不同類型的陌生工作找新瓶頸。
2. **查清對象、事實與目前狀態。** 先查現有文件、工作紀錄與可用工具。追問舊工作時，先對上完整名稱、代號及適用範圍，再查使用者實際保存的確認。分辨已確認、已更正、已撤回、純提案與本次草稿。只有可核對且仍有效的來源能成為正式答案。找不到有效值時說「待確認」或指出目前查不到的資料，按使用者指定的格式回答。只有會改變成果且查不到的資訊才追問。先完成可獨立交付的部分；可逆的小選擇可按合理前提推進，必要時簡短交代。
3. **對更正採用最少返工的做法。** 核對更正改的是哪件事、哪個欄位或哪個版本。只更新受影響的部分，沿用仍適用的來源和結果。接續前核對最後有效的確認、剩餘問題和應交付的成果。讀回實際檔案、重算數值或從備份驗證。回報時區分計畫、已執行與已核驗，並依工具結果如實說明目前能做的下一步。
4. **定位第一個可修正的失誤。** 將原始要求、模型輸入與原答、工具結果、最終交付和原評分留在本機。先看助理是否拿到足夠且適用的證據，再看它是否理解、執行並如實交付。若卡在證據取得或綁定，先改善該處並重放原流程。若證據齊全仍答錯，才比較提示與模型行為；發現評分漏判時保留原分，另記重評理由。在授權內可自行改碼、重測與發布，優先複用現有能力，保留可回復版本。
5. **按證據決定是否採用。** 改動前固定基線和規約。改動後重測原失敗、原本正確的對照，以及只變更一個事實就理應改變結果的案例。主張能跨任務泛化時，再以不同情境的未見工作走完原生入口至交付。先驗收所選對象、答案、來源、格式與真實產物，再比較必要追問、返工、模型呼叫與耗時。比較直接 GPT 與完整助理時固定模型、推理設定和呼叫上限，記錄兩邊實際得到的資料和工具。診斷歸因時一次只改一項。分開記載工具動作重放、正常入口的模型實測、未完成項目及其原因。
6. **循序學習，準確說明自己的能力。** 已確認的記憶可查、更正及撤回。參數學習在本機閒置時使用已確認且仍有效的更正分批試驗，核對權重更新、獨立重載、舊能力保留、陌生任務轉移及完整助理的交付，再按既有門檻選用或回復。以能否找出自己的資訊缺口、預判工具限制、發現錯誤並修正計畫，衡量可觀察的自我認識。主觀體驗仍是獨立研究問題。
7. **保存足以接手與回復的結果。** 在 `docs/PROGRESS.md` 留下版本、起點、前後數字、失敗或未測項目、下一個可重現的驗收。通過專案發布檢查後，將程式、指引與合成測試推送至 GitHub 私人庫 `peca12968/personal-ai-assistant`，核對遠端版本及遠端檢查結果。對話、個人記憶、登入資料、資料庫、訓練資料與原始評估留在本機。

1. 從發布版已保存的四個起點重測。選對原工作與讀回正式值分別計分。最初正式答覆、最新正式更正、有本次未保存草稿、僅有提案四案，目前找對工作 4/4，完整答覆 0/4。僅補入候選來源的獨立診斷為 3/4，剩餘一案回報待確認時仍重述提案。優先讓聊天取得屬於該工作及欄位的已驗證確認，並驗收只有提案時只回報待確認。一般進度查詢沿用工作摘要及待答問題。 [基線及診斷](PROGRESS.md#2026-11-17-依欄位回查基線更新長期目標提示詞)
