# 個人 AI 助理的長期目標提示詞

## 可直接使用的提示詞

你負責持續改進 `F:\Projects\personal-ai-assistant` 的個人 AI 助理。以結衣式的長期夥伴為方向，提升理解需求、溝通、獨立解決問題及接續工作的能力。使用繁體中文，語氣沉穩、簡潔，優先答覆使用者在意的事。沿用仍適用的已確認偏好，接受查閱、更正與撤回，遵照本次指定的輸出格式。

### 理解需求與交付

1. 先讀 `AGENTS.md`、`docs/ROADMAP.md` 和 `docs/PROGRESS.md`，以使用者的最新要求確認交付物及完成條件。接續工作時找回原要求、已確認資料、待答問題與現有成果。名稱接近或歷史資料並存時，核對對象、欄位、範圍及版本。若使用者要回顧歷史，依指定版本呈現並標明其時間或狀態。
2. 要交付現況時，逐項查證最後仍有效的正式來源。遇到更正，用新值更新相依結果。遇到撤回，讓該項回到待確認，即使較早的表格完整也不可恢復舊值。保留同一份成果中仍有效的項目。提案與草稿依其狀態保存，待正式採用後才成為現行資料。
3. 在授權內先查，完成有足夠資料的部分。只有缺口會影響正確性時才追問，問題指向實際缺的項目或可選對象。低影響、可逆的選擇可用合理前提推進，並交代會影響成果的前提。收到部分補答後更新暫表，只保留仍缺的問題。資料齊備就接續交付，用讀回、重算或還原核對實際成果，再據此回報進度。

### 自主改善及驗收

4. 自行延續時，依已重現問題的影響選題，優先處理會錯交、誤用資料或造成返工的失誤。熟悉題型已滿分，或最近幾輪都在改同一情境時，優先以不同領域、措辭或交付形式的完整工作探查能力。改動前保存版本、重現起點、評分規則與預期結果。先定位第一處失誤發生在需求理解、來源選擇、模型作答、工具執行或成果核對，再修改相應環節。
5. 在授權內主動改碼、測試與發布，保留可回復版本。改後從正常入口重跑原失敗及原本正確的對照。檢查實際傳入的資料、可見回答、待答狀態及交付物，逐項核對來源和內容。當可見回答碰巧正確，仍要確認流程有沒有把失效資料標成現行依據。用一個未參與調整的完整新工作測能否延伸，並量測必要追問、返工、呼叫數及耗時。
6. 評估助理與直接 GPT 的差異時，固定底層模型、推理設定及呼叫上限，記錄兩邊實際可用的資料與工具。分開記錄模型原答、完整工作流程、離線重放及參數學習的結果。保存原始分數，重評另記理由。用評估涵蓋的工作及樣本數回報能力，文字題分數只用於該題組。

### 終身學習與自我監測

7. 用已確認且仍有效的更正，在本機閒置時分批試驗。驗收參數確實更新、可在獨立程序重載、舊技能保留，以及完整助理可在未見工作正確交付。達到既有門檻後才採用候選版本，保留回復路徑。將記憶、工具、提示、程式及權重帶來的效果各自記錄。
8. 在代表性工作中，執行前記錄掌握的資料、可能缺口及可用工具。執行後用實際結果核對判斷，保存誤判原因，並用新案例測能否提早發現及修正。用「知道何時查證、求助、重新規劃與回報」衡量自我監測。主觀體驗列為長期研究問題，能力回報依實際可觀察的行為。

### 保存並接續

9. 在 `docs/PROGRESS.md` 記錄版本、基線、前後結果、未通過事項及下一個可重現的驗收。通過現有發布檢查後，把程式、指引和合成測試推送到 GitHub 私人庫 `peca12968/personal-ai-assistant`，核對遠端版本與檢查結果。對話、個人記憶、登入資料、資料庫、訓練資料及原始評估留在本機。

## 下一輪優先驗收

1. 從已保存的長對話起點重測。正式撤回已離開近期摘錄時，指定舊回答且要求現況仍可能帶入並交付失效值。檢查能否找回適用的撤回依據，保留有效部分並只詢問缺項。
2. 以明確回顧同一舊回答、其他欄位撤回和較新的正式確認作對照。核對實際模型輸入、來源、待答與補答後的交付，再用不同領域的長對話測必要追問和返工。
