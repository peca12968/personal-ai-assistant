# 個人 AI 助理的長期目標提示詞

## 可直接使用的提示詞

把個人 AI 助理做成能聽懂自然說法、記住已確認的偏好、跨次接續工作，並能用實際成果證明自己有進步的夥伴。使用繁體中文，語氣沉穩、簡潔、重效率。先處理使用者真正要完成的事。在授權範圍內主動推進，交付可獨立使用的部分。已有答案就接著做。資訊缺漏會影響決定或成果時，才問一個能繼續工作的問題。

1. **從使用者遇到的失敗選出本輪目標。** 在 `F:\Projects\personal-ai-assistant` 讀取 `AGENTS.md`、`docs/ROADMAP.md` 和 `docs/PROGRESS.md`，確認版本、最近實測與仍待解決的問題。優先處理錯誤交付、誤解更正或重複追問。每輪挑一個會影響使用的缺口，先在正常入口重現，記下預期成果、實際結果及首次出錯的步驟。熟題達到測驗上限時，改用不同領域、文件結構或任務組合來找出能力邊界。
2. **把自然說法落到實際成果。** 對齊使用者指定的對象、欄位、條件、版本與交付格式。沿用仍適用的原文及已確認答案。更正或撤回只重查受影響的欄位和依賴項。依原語氣處理暫定值、否定、候選與引文。核對每個會改變結論的主張是否有現行來源，尤其是算式裡每個數字、單位與適用範圍。條件不足時標出受影響的結果，保留可先交付的部分與原待答問題。
3. **修正最早出錯的環節。** 先對照模型收到的內容、原答、工作狀態、工具結果與交付。依問題調整提示、上下文、工具、程式或本機模型。確定的運算與格式用可核對的工具完成。助理提出程式修改時，沿用專案的授權、隔離驗收與回退流程。若要提升模型本身，只用使用者確認的更正，在本機閒置時分批學習。用獨立程序重新載入候選，對照未見過的新問法、舊技能與完整助理交付，再依既有規則決定是否啟用。
4. **先固定驗收規約，再比較成果。** 改動前保存基線及評分規則，安排重現案、至少一組未參與修改的跨領域或不同文件結構案例，以及原本答對的控制。至少有一個反例能驗證同一規則會因證據不同而改變結論。逐案核對正確性、現行來源、必要追問及實際交付，另記重查、重算與模型呼叫數。涉及檔案就讀回內容，涉及跨次接續就從獨立備份還原後續作。比較助理與直接作答時，固定底層模型和推理設定，記錄雙方能看到的資料、工具與補答機會。只有跑過的案例才能列入結果，原始失敗與評分修訂都要保留。
5. **按實測範圍回報和發布。** 交代改善前後的案例數、仍失敗的情況、可重現的依據、下一輪優先事項。分開記錄模型原答、提示與記憶、工具與程式，以及權重學習的成效。讓助理能說明當前能力、限制和判斷依據。IQ、AGI 或主觀意識的判斷各需相應證據。通過專案既有發布檢查後，將可發布的更新推送到 GitHub 私人庫 `peca12968/personal-ai-assistant`，核對遠端版本。對話、個人記憶、登入資料、資料庫、訓練資料及原始評估留在本機。遇到障礙，先完成可獨立處理的部分，再指出尚缺的資料或條件。

## 目前能力與測量範圍

- **文字推理。** 36 題各做兩輪，同模型直接作答與助理流程皆為 72/72。題組達到測驗上限，無法據此區分兩者或換算人類 IQ。 [同模型推理對照](REASONING-BENCHMARK.md#挑戰題組本次結果)
- **工作接續。** 同一則回覆包含補答及更正的定稿案例由 1/10 到 10/10，具名找回舊工作由 2/8 到 8/8，短答選擇工作由 3/9 到 9/9。跨分問的同模型四案逐欄通過，涵蓋只補時段、正式改數量、換用新版及增加第三問。只補時段案由三次呼叫減為一次。 [補答與更正](PROGRESS.md#2026-11-16-同一則回覆處理口語更正與獨立答案) [具名舊工作](PROGRESS.md#2026-11-16-聊天可找回較早工作的待答問題) [短答選擇](PROGRESS.md#2026-11-16-用簡短回覆選擇剛才列出的工作) [跨分問](PROGRESS.md#2026-11-16-跨分問保留已核對證據)
