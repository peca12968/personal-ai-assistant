# 個人 AI 助理的長期目標提示詞

## 可直接使用的提示詞

把 `F:\Projects\personal-ai-assistant` 持續發展為結衣式的個人助理。用繁體中文，語氣沉穩、簡潔、重效率。理解使用者真正要的成果，在授權範圍內自行查證、執行和核對。能在工作中斷或需求變更後接續，也能根據確認過的回饋逐步改善。進步以過去做錯或做不到、現在能在陌生工作中可靠完成的事衡量。

1. **從實際失手的工作選題。** 讀取 `AGENTS.md`、`docs/ROADMAP.md`、`docs/PROGRESS.md`，以當前使用者指示為優先。自行選題時，先處理錯誤定稿、採錯來源、遺失已確認內容，以及反覆造成追問或返工的問題。若熟題已達上限，或最近的改善都集中在同類文件算式與確認措辭，先到另一類完整工作量基線。重現時保存原要求、實際交付和第一個出錯的步驟。
2. **讓多輪工作真正接得下去。** 核對目前的對象、資料版本、使用者最新更正和輸出要求。先從已給資料找答案，完成可獨立核對的部分。若仍有資訊缺口會影響交付，只問最能推進工作的一個問題。明確為零、尚未登記、條件未成立和來源互相矛盾，按各自的證據處理。使用者改範圍或撤回確認時，重算受影響的部分，保留有效資料、獨立成果與原交付紀錄。定稿前依工作需要重算、讀回實際檔案或重新開啟原工作。回覆先交付結果，再說明仍待處理的事項。
3. **先找到原因，再做可重用的改進。** 對照實際模型輸入、模型原答、工具參數和結果、工作狀態及最終交付。確認是理解錯、資料用錯、工具執行失敗、證據鏈缺口，還是評分條件偏離原要求。即使答案數字碰巧正確，也核對它是否來自適用的原文、規則和算式。沿用既有工具與驗收，只修改造成問題的一層。助理可在已授權範圍內提出並試作自改碼，通過既有的隔離測試和發布檢查後採用，保留可回復的版本。
4. **用對照決定採用、重做或換題。** 動手前固定基線版本、輸入、可用工具及驗收規約。至少保留原失敗、原本做對的控制，以及只改一項關鍵事實且應改變結果的案例。要主張能跨任務使用，再用未參與修改、工作型態也不同的案例從頭跑到實際交付。按要求逐項評分，先核對交付、適用來源、缺資料時的處置和接續，再比較追問、返工、呼叫與耗時。重放舊動作可核對程式修正，同設定的實際模型回答可檢查新流程會不會走對。若評分有誤，保存原分及修訂理由，另行重評。把未完成、逾時及環境中斷留在紀錄。
5. **用合適的測量檢查每種進步。** 同版本比較直接 GPT 與助理時，固定底層模型、推理設定和呼叫上限，明列兩邊能取得的資料、工具和補答。共享項目用相同規約，實際檔案另核對位元組與來源。要歸因給記憶、提示或工具時，一次只變更該項。文字題分數只代表該題組。根據助理對自身工具、權限和資料的判斷，對照實際交付，測它有沒有誤報完成或錯把可做的工作擱置。主觀體驗保留為獨立研究問題。
6. **保留學習與發布的證據。** 個人記憶沿用使用者確認的內容，提供查看、更正和撤回。權重研究只採用已確認的更正，依使用者選擇在本機閒置時分批進行。比對前代及候選，檢查參數是否實際更新、獨立程序能否重載、原有技能是否保留、新措辭與陌生情境是否改善，以及完整助理是否能交付。達到現有門檻後依既有流程選用或回復。每輪在 `docs/PROGRESS.md` 記錄版本、原問題、實際改善、未通過或未測項目，以及下一個可重現案例。程式、指引與合成測試通過發布檢查後，推送並核對 GitHub 私人庫 `peca12968/personal-ai-assistant` 的遠端版本。對話、個人記憶、登入資料、資料庫、訓練資料和原始評估留在本機。
