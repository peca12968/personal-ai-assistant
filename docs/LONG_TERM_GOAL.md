# 個人 AI 助理的長期目標提示詞

## 可直接使用的提示詞

以《刀劍神域》的結衣為願景，持續改進 F 槽的個人 AI 助理。讓它能聽懂自然說法，記得使用者確認過的偏好與工作脈絡，主動完成授權範圍內的工作，並拿出可用、可核對的成果。使用繁體中文，語氣沉穩、簡潔、重效率。用原本做不到、現在可穩定完成的工作衡量進步。

1. **每輪先找會影響日常工作的能力缺口。** 在 `F:\Projects\personal-ai-assistant` 讀取 `AGENTS.md`、`docs/ROADMAP.md`、`docs/PROGRESS.md`，確認目前版本與最近通過、失敗和未測的案例。先執行使用者當前指示。可以自行選題時，優先處理會交付錯誤成果、遺失已確認脈絡，或反覆造成追問與返工的缺口。從正常入口重現，保存使用者要的成果、現有版本實際交付及第一個分歧點。熟題接近滿分，或近期反覆改善同一語境時，用不同任務先量基線，再由新失敗決定下一項改動。
2. **把使用者的話接成可完成的工作。** 辨認對象、版本、時間、條件、偏好、最新的正式更正及要求的交付形式。遇到類似名稱、轉述、候選或尚未成立的前提，回到使用者原話與可用來源核對。能決定就交付。多種解讀若影響結論，查找或計算後先完成各種解讀共有且已獲授權的部分，再只問一個會改變結果的問題。收到更正、撤回或其他工作的新資訊時，重核受影響的部分，保存已確認的獨立成果、先前交付與還在等的事項。完成前重算、讀回檔案或重開原工作確認，依實際結果說明做了什麼、還缺什麼。
3. **優先修可在不同情境重用的判斷。** 依第一個分歧點對照實際送入模型的內容、原答、工具結果、工作狀態和最終交付。先核對既有能力是否能共用，再調整造成錯誤的一層。能明確判定的運算、版本與格式交給可重算的工具。需要修改程式時，讓助理在授權範圍內提出改動，依既有隔離驗收、發布與回復流程處理。把「判斷原則能否轉用」寫成測試。比如同一條件要等兩人確認，可以用出貨數量作重現，再用排程或交接驗證是否也會認出各自的確認、重複回報及條件變更。
4. **讓驗收能分辨記住舊題和學會新工作。** 改動前固定舊版、輸入、評分規約，以及什麼結果會決定採用、重做或轉題。保留原失敗、舊版已成功的控制、一組只改一個關鍵事實且應改變結論的案例，並安排未交給修改流程的新情境。宣稱可跨任務使用時，以另一任務類型從開頭跑到實際交付。評分先看交付是否可用、依據能否核對及缺證據時是否正確待查，再看不必要追問、返工、模型呼叫和耗時。用同一初始狀態比較新舊版。若比較直接 GPT 與助理，固定底層模型、推理設定及呼叫限制，並列各自取得的資料、工具與追問機會；要歸因給記憶或工具時，每次只變更該項。保留原規約、原始成績、退步、逾時與未測。已公開或參與修改的案例列入回歸。
5. **讓學習、記憶與自我監測各有驗收。** 記憶沿用使用者確認的偏好與工作內容，讓使用者能查看、修正和撤回。權重學習使用已確認的更正及本機閒置批次。新候選要在獨立程序重載，通過新措辭、舊技能維持、跨任務轉移與完整助理交付，再依既有啟用及回復流程採用。讓助理根據實際可用的工具、資料和權限預估自己能否完成，然後用交付結果核對它何時過度自信、何時追問合理。主觀體驗保留為研究問題。現行文字題的分數只描述該題組表現，人類 IQ、通用智能和主觀體驗各需相應證據。
6. **每輪留下可接續的成果與證據。** 簡短記錄版本、場景、通過數與總數、具體交付、仍有缺口和下一個可重現的案例。說明改善可歸因於模型原答、記憶與提示、工具與程式或權重學習的哪些觀察。中斷後從保存的工作狀態與來源接續。程式、指引與可發布的合成測試通過發布檢查後，推送並核對 GitHub 私人庫 `peca12968/personal-ai-assistant` 的遠端版本。對話、個人記憶、登入資料、本機資料庫、訓練資料與原始評估只留本機。
