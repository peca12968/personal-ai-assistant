# v0.4 文件分析評估

日期：2026-11-02。資料為 `evals/documents.json` 的 20 個合成案例，不含使用者私人文件。使用已登入的真實 Codex 引擎，每題執行一次；開發代理閱讀實際答案並依既定 rubric 評讀，並非使用者驗收、獨立評審或盲測。

## 結果

- 61 項程式測試通過，包含檔案上限與編碼、對話隔離、同名文件、快照、重新匯入、行號、來源範圍與錯誤引用。
- 文件證據選取 20/20；另有記憶 30/30、上下文 10/10。證據存在不是答案正確率。
- 真實文件回答 20/20 符合本輪 rubric。所有實際引用均能對照當次送出的來源行號。
- 原始回答與逐題評讀留在本機忽略目錄 `data/evaluations/documents-live-v4.json`，不推送 GitHub。

## 限制與重跑

這組開發案例較小，與實作共同設計；沒有舊版對照或重複取樣，因此不能宣稱整體模型推理能力提高或通用成功率為 100%。指令干擾案例只驗證這一種輸入，不是完整安全保證。引用檢查只驗證來源與行號存在，不能驗證語意支持、算術或完整性。實際測試不執行系統修復、檔案搬移或部署。

```powershell
python scripts/evaluate_documents.py
python scripts/evaluate_documents.py --live --report data/evaluations/documents-live.json
```

第二個命令會使用 Codex 帳號額度；產出報告的 `human_grade` 預設空白，必須閱讀答案後另記評讀，不自動把有回答當作通過。


## v0.16 相鄰條文對照（2026-11-03）

新增四個合成案例，文件證據選取由二十題增為二十四題。每題同時加入八份文件，使主規則與緊鄰條文跨過三十行分段邊界；另保留超出相鄰範圍的限制案例。

原版真實回答承認只看見第 1–30 行，請使用者補上第 31 行；並未胡亂猜測，但例外其實已在匯入的文件中。改版後在剩餘字數內補入前後最多兩行完整原文，原題直接正確區分一般案件十四天與審查中案件保全至結案。另三題分別正確處理測試／正式環境適用範圍、文件內的改寫指令，以及超出兩行的未知例外。所有實際引用範圍有效，開發代理閱讀四個答案後依既定標準記為通過。

原題改前一次、四題改後各一次，未重複取樣；這是有來源快照的開發對照，不是獨立盲測或通用正確率。原版的未知回答不視為捏造或推理錯誤。完整回答、來源快照、程式指紋與評讀保存在忽略的 `data/evaluations/doc-neighbors-v016`，`human_grade` 仍為空。

字數用盡、長行或更遠的條款仍可能未提供。檢查會依實際提供範圍保留覆蓋不足標記，不因補入一部分上下文就宣稱完整讀過文件。長行片段不自動擴充；引用範圍檢查仍不能證明語意支持。


## v0.17 精確文件範圍（2026-11-03）

原版探測發現：單獨 `[D1:L33]` 可因詞彙碰巧選到該行，但加入原題關鍵字後只提供 L1–L32；指定 L1–L33 也可能僅有 L29–L33。這是選取證據不足，沒有將未測的原版模型答案宣稱為錯誤。

新增當前問題中的來源編號／行範圍辨識，支援引用格式、中文阿拉伯行號、英文及全形數字；先依目前對話的匯入副本取回完整範圍，再分配一般片段。來源不明確不猜檔名，歷史問題的來源引用不會自動成為本次硬性要求。未匯入、越界、逆序、過長或超出片段／字數預算有明確狀態，並加入歷史快照。

九項新測試檢查解析、同名來源辨識、原文與完整性、共用預算、長行、去重與包含範圍、八範圍上限、跨對話、原檔變動、重新匯入、移除及歷史快照；文件選取集擴為二十九題。

初次真實回答指出兩個驗收細節：無效來源仍以引用格式重述，會觸發範圍警告；原歧義案例只有一個文件實際有第33行，無法驗證多候選情況。保留初次觀察與案例，改善錯誤說明提示，將歧義案例補為兩份都有該行的文件。最終五題各一次真實回答逐題開發評讀通過：精確單行、完整範圍、未匯入與越界、過大範圍、真正多文件歧義。沒有把前後不同案例當成同一批能力分數比較。

完整資料與程式／提示指紋在本機忽略的 `data/evaluations/doc-ranges-v017`，最終報告 `final-live.json` 的 `human_grade` 仍空白。這是有限格式的讀取功能與開發驗收，不是任意自然語言定位、語意引用驗證或整體模型能力分數。
