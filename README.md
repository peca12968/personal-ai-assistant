# 個人 AI 助理

放在 F 槽的獨立 Python 桌面專案，使用已登入的 Codex 作為推理引擎。

## 自主工作中途補充與更正（v0.31）

在「自主目標」選取待開始、已暫停、流程未完成或等待補充的目標，按「補充／更正此目標」。核對原目標、已記錄步數、待回答問題與舊補充後，追加新的條件，例如「更正：人數改為12人，費率改為90元，其他要求照舊」。每次最多4000字，全部補充累計最多12000字；保存時記錄UTC時間與當時步數。

保存後不會自動開始；回原視窗按開始／接續即可讓模型參考最新明確更正。舊目標、步驟、計算與補充保留為歷史，條件改變時需重新計算。另一視窗已修改或推進工作，會拒絕過期保存；按「重新載入目標」核對最新資料，未送出的補充草稿會保留。

工作中先停止並等候結束；已有成果用下一階段，來源變更或累計32步已滿則另建目標。若助理仍有待回答的問題，此入口只追加條件，不會替你回答；請在原視窗「保存補充」回答後再接續。補充不增加檔案／CSV權限、不改匯入來源、不覆寫已存檔案；一般聊天也不會自動改寫自主目標。紀錄隨本機備份保存，只有明確建立下一階段時才沿用至該階段。

命令列先用 `python -m assistant --session 對話編號 --goal-guidance-status 目標編號` 查看快照，再以 `--amend-goal 目標編號 --goal-guidance "更正內容" --goal-fingerprint 讀到的指紋` 取代前述狀態選項。兩次都保留 `--session`，自訂資料目錄時也需保留 `--data-dir`；這些命令不啟動模型。

## 主動回顧提醒（v0.30）

開啟「記憶與夥伴設定 → 主動回顧提醒」，勾選啟用、設定電腦本地時間（例如20:00）並儲存。預設關閉；只在應用開啟時每30秒檢查，忙於聊天、這個應用啟動的自主工作或記憶整理時延後。過了當天設定時間才開啟，會提醒當天一次，不補發過去多天；沒有可回顧項目就不提醒。

主畫面出現可捲動的提醒區，列出最多三個目標的下一步及總數，優先顯示需要補充、成果待確認等項目。已收起或紀錄為running的目標不列入；後者不是程序仍存活的證明。提醒顯示期間會重新讀取目前紀錄，避免一直顯示已收起的工作；不把其他對話內容插入目前聊天。

「查看全部」開啟最新回顧清單並關閉當日提醒；「15分鐘後提醒」可稍後再看，「今日關閉」停止當日提醒。重新開啟程式保留當日及稍後紀錄，多個程式視窗共用同一則提醒狀態；過期視窗的操作不能覆蓋其他視窗的新選擇。跨午夜的稍後提醒會記為新一天；修改時間或停用再啟用不重複當天已發提醒。停用會清除目前提醒及稍後時間，設定可重新載入以處理多視窗變更。

這是本機依工作狀態列出的回顧入口，不呼叫模型、不自動執行或改碼，也不改動目標狀態。關閉程式或電腦睡眠時不會通知，尚無作業系統通知或背景常駐工作。提醒設定與狀態納入本機備份，排除於GitHub；舊版資料庫升級維持未啟用。

## 從對話整理及更新可追溯的長期記憶（v0.29）

左側「從本對話整理記憶」→「擷取本對話並整理草稿」，會固定保存同對話的有限近期討論、較早更正及回饋，讓模型提出最多8項事實／偏好／經驗。每項需附使用者原話或回饋引文；助理猜測不能作為來源。來源範圍沿用對話交接的16則／12000字、較早六則更正及最近三筆回饋限制，可按「查看完整來源快照」檢查省略標記。這不代表讀取全部經歷。

選取一項草稿，核對原句與可能相關的既有記憶，修改內容、類型和到期日，再按「將這一項保存為長期記憶」。未保存的草稿不會加入回答。相關記憶是有限檢索，不是完整矛盾檢查。預設新增模式不改動其他記憶；相同有效內容沿用原編號，重複保存同一草稿不會新增第二份；若該記憶後來刪除，舊收據也不會把它重新建立。

若新資訊取代舊資訊，在「保存方式」明確選擇「更新 #編號」，核對更新前內容後按「更新選取記憶 #編號」。只更新選定的一筆，保留原編號、建立時間及啟用／停用狀態，並保存更新前快照。選取對象會先帶入舊到期日，可自行修改或清空；切回新增模式會清空帶入的到期日。另一視窗已修改或刪除時會拒絕保存，請按「重新載入記憶清單」再核對；不會自動猜測要覆寫哪筆，也不會順便合併其他矛盾資料。停用狀態不會因更新而重新啟用。更新歷史可在「長期記憶 → 查看整理來源」查看，普通聊天只按既有規則檢索目前記憶。

保存後可跨對話選用。在「長期記憶」選取該項並按「查看整理來源」，可查看當時草稿、接受後文字與原話；後來編輯、停用或刪除不會回寫歷史來源。刪除記憶只讓未來回答不再選取它，原對話、草稿與收據仍留在本機及既有備份。需要永久移除歷史資料時，不能只依賴刪除記憶。

草稿生成可停止；失敗可選取「重試所選來源」，仍使用原快照。來源不會隨後來聊天更新，需要最新背景時另建一份。整理中的紀錄不證明程序仍存活，重試會取得排他鎖；本機中斷不代表已確認雲端請求結束。視窗顯示最近20份，完整草稿與收據包含在本機備份，舊版資料庫可遷移。

引用核對只證明原文存在，不代表內容理解一定正確；仍由你核對後保存。整理不會自動訓練模型、更新夥伴設定或執行原話中的操作。普通聊天沒有自動整理／保存；「記住：…」明確指令仍可直接保存。所有對話、草稿、記憶及來源收據都排除於GitHub。

## 把你的更正用在下一次回答（v0.27）

按「需要改進／更正」保存具體更正後，同一對話後續回答會參考最近最多三筆非空的負評更正。這些回饋獨立於近期16則對話，不會因多聊幾句就完全消失；每筆帶入更正前1000字與被更正的舊回答前1200字、回答編號、時間及省略標記。按回饋更新時間選取，同秒以回答編號排序；新問題及明確的新決定仍優先。明確換話題或要求不沿用前文時，這次不帶入舊回饋。

在「回饋紀錄」選取舊回答，可編輯上方「修改已保存更正」並按「保存更正」，或按「停止帶入這筆更正」清空。編輯器會核對原資料，避免覆蓋另一個視窗的新修改。下方「改善描述」仍是改碼案例的草稿，編輯它不等於保存更正。新回答保存實際採用的參考快照；既有回答、已建立目標及另外保存的長期記憶不會被回寫或刪除。若曾選擇另存長期記憶，需在記憶介面分別管理。

「帶入對話建立目標」也會固定保存當時有效的回饋；普通新目標不暗中帶入。舊版目標原本沒有回饋快照時維持原樣。更正是使用者提供的歷史資料，舊助理回答不是已確認事實；回饋不會啟動工具、改碼、改名或自動建立記憶，也不代表模型權重已訓練。回饋及快照只留在本機／本機備份，開始回答或已選目標時才把有限參考傳給模型，不上傳GitHub。

## 設定上限後持續執行（v0.26）

在「自主目標」選取已保存的工作，設定「新增最多步數」與「最多分鐘」，按「開始持續執行」。預設新增最多24步、30分鐘；可設1–32步、1–120分鐘。它會連續觀察與選擇工具，不需要每6步手動按接續。原本逐輪1–12步的入口仍可使用，兩者共用每個目標累計32步上限。

完成成果、需要你的補充、參考副本改變、連續三次工具錯誤、時間／步數上限或手動停止都會結束此次執行。一般引擎錯誤不會自行重試；一次工具錯誤後仍可自行修正。停止原因、設定、起訖步數與時間保存在本機，目標視窗／CLI顯示最近10次紀錄，完整歷史包含在本機備份。成果待確認仍不等於內容已驗收。

```powershell
python -m assistant --run-goal 目標ID --session 對話ID --continuous-steps 24 --continuous-minutes 30
```

這是你啟動後、應用程式開啟期間的持續工作；關閉會要求停止，重新開啟不會自動開工。時間上限會中止等待中的本機模型程序，清理程序仍可能需要數秒；本機停止不代表已確認雲端請求終止。已執行的動作與文件會保留。整次持有同一目標的工作鎖，避免其他視窗重複執行；中斷紀錄只在重新取得鎖時標記，不能從「執行中」文字判斷是否仍存活。此次夥伴設定固定，下一次開始才採用新設定。

持續執行沿用建立目標時的文件／CSV範圍，不自行產生新目標、增加權限或啟動自我改碼，也沒有定時排程或登入後自動啟動。

## 從聊天接續自主工作（v0.25）

討論清楚後，按左側「帶入對話建立目標」。會開啟可編輯草稿，預填目前聊天輸入中的文字；輸入為空時，預填依已確認需求接續工作的通用目標。原輸入及其他目標視窗的未保存草稿不變，不會自動送出或開始。確認目標、所需CSV及交付形式，按保存後查看帶入背景，再開始一輪工作。

也可從「自主目標」勾選「新目標帶入本對話背景」。保存目標時會在同一交易固定當時的近期討論、較早更正摘錄，以及手動保存的對話目標／限制／決策，附使用者或助理角色、訊息編號、時間與省略標記。助理可沿用已確認的決定，不因文件未記錄私人選擇而重問；舊助理建議不當成使用者確認，本次目標及補充優先，文件費率或引用則重新查讀目前來源。

帶入範圍為近期最多16則、每則最多2000字、合計12000字，另保留最多六則更早、以明確更正句型開頭的使用者原文，每則1000字；這個字面選取不保證每則語意都真的是更正。手動對話目標三欄各最多2000字。本機記憶指令及其回覆排除，其他對話不帶入；省略的內容不等於從未提供。快照不是完整聊天，也不會在建立後隨新聊天或修改目標摘要而自動更新。

普通新目標不會自動取得這份背景。建立下一階段時也不暗中複製原快照；如要同時帶入目前討論及所選上一階段成果，需明確勾選，再使用下一階段按鈕。帶入對話不增加工具、檔案或CSV權限，也不把舊引用當成本階段已讀的證據。

快照保存在本機並納入備份，開始工作時會傳給模型，不上傳GitHub。之後刪除長期記憶或更改偏好不會抹除已建立的目標快照、一般舊對話或備份；建立新目標時會擷取當時資料。還原舊版無此欄位的備份，原目標維持未帶入聊天。

```powershell
python -m assistant --new-goal "沿用剛才決定的方案，計算12個月費用" --from-chat --session 對話ID
python -m assistant --goal-status 目標ID --session 對話ID
python -m assistant --run-goal 目標ID --session 對話ID
```

## 自主CSV分析（v0.24）

先在目前對話的「參考文件」匯入CSV，再到「自主目標」選取「新目標的CSV分析來源」。例如輸入「只保留已付款資料，依區域加總金額、列前兩名，同時列全部資料及前兩名各自的筆數與平均」，保存並開始。選取CSV代表允許這輪依目標自行保存分析計畫及執行；普通聊天不會啟動。若只要求規劃，模型應保存計畫並說明尚未計算。

模型先以型別化資料保存欄位、篩選與排序等規格，再另呼叫執行工具，收到實際結果後整理報告。工具沿用已驗證的CSV計算流程：最多6個AND篩選、分組筆數、加總、算術平均、排序及前幾名；平均固定四位小數、ROUND_HALF_EVEN，總平均依保留資料的加總／筆數計算，不是組別平均的平均。零筆資料的平均為未定義，錯誤數值不跳過或當成零。CSV彙整工具沒有中位數、多表連接、去重及其他平均規則，不能偷偷替代；資料少且可以完整讀取時，模型可自行使用原有讀取／四則計算工具推導所需答案，明示依據，不把推導說成CSV彙整工具已驗證。資料或運算不足時才提出必要問題。

每個目標明確選取一份已匯入副本，最多4份不同分析計畫；相同規格重用，成功結果重試不重算。副本上限2MiB、50000筆、200欄、5000組，計算限時30秒、完整結果上限4MiB。外部原檔不重開；重新匯入或移除來源後需另建目標，下一階段不暗中繼承CSV選取。取消、失敗與未完成紀錄保留，可在原目標的鎖可取得後接續；未完成計畫沒有成功數值。

「查看CSV計畫／結果與匯出」可檢查每份計畫並另存完整JSON，使用新檔名、寫入後讀回核對。完整結果與指紋保存在本機；傳給模型的每頁最多20組，超過200字的組名附省略標記，不影響完整結果。分頁的總額與平均仍指全部保留資料／前幾名所選組別，不是該頁小計。模型可搭配「交付文件」建立文字摘要；完整結果尚未另存時，不能聲稱已匯出檔案。匯出不呼叫模型。

選取CSV的欄名、規劃及工具結果會送給模型；透過原本文件工具讀取的片段也會傳送。完整計畫、結果、有限匯出紀錄納入本機備份，不上傳GitHub；還原後可匯出已保存結果，不需原始外部CSV。只核對資料與計算不等於模型報告已獲使用者驗收。

```powershell
python -m assistant --new-goal "按區域分析已付款金額" --csv-document 1 --session 對話ID
python -m assistant --run-goal 目標ID --session 對話ID --goal-steps 8
python -m assistant --export-goal-csv 計畫ID --csv-goal 目標ID --session 對話ID --output "F:\Reports\analysis.json"
```

`--csv-document` 使用目前對話實際匯入的文件編號；範例的1不是固定編號。目標行動紀錄及CSV結果視窗可查看計畫編號。

## 接續與回顧（v0.23）

重新開啟 `Start.cmd`，左側「接續與回顧（數量）」會提示同一份本機資料庫尚未收起的自主目標。可跨對話查看待補充、已暫停、尚未開始及成果待確認的工作，不必逐段切換尋找。選取項目後按「查看所選目標與下一步」，會開啟對應對話的自主目標，不切換目前聊天，也不自動呼叫模型或開始工作。側欄可捲動，較矮視窗仍能找到備份等入口。

回顧提供目前可採取的下一步：等待問題先補充，已達32步上限或匯入來源改變時需另建目標，已交付成果則查看或建立下一階段。記錄為「自主工作中」不等於程序仍活著；回顧不探測或重設執行狀態，實際接續仍檢查排他工作鎖。曾交付的檔案也不會因回顧而被當作目前仍存在或完整。

「暫時收起」只在此版目標狀態下移出預設回顧，不會停止、刪除、完成或驗收目標。補充、步驟、成果、已保存文件紀錄或匯入來源有改變時會再次顯示；單純修改未重新匯入的外部原檔不算更新。可勾選「也顯示已收起項目」，再選取「重新顯示在回顧」。資料變更後舊清單不能直接收起，會要求重新整理，避免漏看新進度。

每頁最多100項，可翻頁；完整內容在各目標視窗。主視窗數字與回顧清單是最近讀取的紀錄，按「重新整理」取得更新。收起紀錄納入本機備份，舊版備份沒有此紀錄時所有目標正常顯示。跨對話回顧不送給模型、不加入目前聊天的參考內容、不上傳GitHub；這是開啟應用時的本機提醒，尚非背景排程或自行執行工作。

命令列也可離線查看同一資料庫的全體目標：

```powershell
python -m assistant --review-goals
python -m assistant --review-goals --review-hidden
python -m assistant --review-goals --review-offset 100
```

## 自主交付文件（v0.22）

在「自主目標」填寫需求，例如「比較已匯入的方案、計算12個月費用，交付附來源的Markdown文件」，勾選「新目標需要交付文件」，再保存與開始。模型可自行查讀、計算、建立文件，最後列出交付檔名；每次存檔與交付都會讀回UTF-8位元組，核對內容、大小及SHA-256。使用「開啟成果資料夾」取得文件。

目前支援Markdown（`.md`）、純文字（`.txt`）及合法JSON（`.json`），每個目標最多4份、每份最多12000字。位置固定在目前資料庫旁的 `autonomy-artifacts/目標ID/`，預設位於專案的 `data` 內；不能指定其他路徑。同名同內容可重試；不同內容保留原檔，需改用新檔名。普通目標維持視窗文字成果；下一階段是否交付文件由建立時的勾選決定，不會自動繼承上一階段權限。

內容會先保存於資料庫再寫檔。中斷或停止後，已保存的內容、草稿及已建立檔案保留，不自動刪除；接續時可重新核對。檔案與資料庫不是同一筆原子交易，因此曾核對成功不保證目前仍存在或未變動。交付會再次核對所列檔案，與保存內容不同時不標記交付成功。這只驗證檔案完整性，內容仍待你確認。

本機備份包含已保存文件的內容與指紋，不直接打包成果資料夾。還原後，選取目標按「核對／重建已保存文件」，會重建缺少的文件並核對既有同名檔案，不呼叫模型、不重新查證歷史內容；包含該目標所有已保存文件，可能含未交付草稿。文件、對話及資料庫都不發布GitHub。

```powershell
python -m assistant --new-goal "比較方案並交付 cost-comparison.md" --deliver-files --session 對話ID
python -m assistant --run-goal 目標ID --session 對話ID --goal-steps 8
python -m assistant --rebuild-goal-files 目標ID --session 對話ID
```

## 夥伴設定（v0.21）

重新開啟 `Start.cmd`，到左側「記憶與夥伴設定 → 夥伴設定」。可保存助理稱呼、希望助理怎麼稱呼你、平常語氣、回答長度、互動方式，以及最多1200字的補充溝通偏好。助理稱呼與對你的稱呼各最多40字；對你的稱呼可留空。未儲存時使用程式預設「個人 AI 助理、溫柔自然、依需求調整」，不把預設說成你已確認的個人資料。

設定套用到同一份本機資料庫的所有對話，下次提問或新一輪自主工作時生效；正在進行的一輪不會中途換設定。本次明確要求優先，例如只回算式、不要稱呼、只想傾聽或改用詳細步驟。普通聊天可暫時遵循新要求，但不會自動永久改名或修改設定；跨對話保存請在此視窗按儲存。

設定保存在本機、納入本機備份，不推送GitHub；回答時會送給模型。「查看本次參考 → 夥伴設定」可看當時快照，自主步驟也保存實際採用的版本。新一輪採用目前設定，不重送舊步驟內的設定快照；舊對話與成果本身仍可能含有當時的稱呼。重設只更新目前預設，不刪除歷史對話、工作紀錄、匯出或備份。兩個視窗同時修改時，舊視窗會提示重新載入，避免覆寫新內容。

語氣與稱呼是溝通設定，不代表主觀意識、事實證據或新工具權限。程式不會因補充偏好要求而自動啟動工作、改碼、發訊息，或把未執行的事情說成完成。

命令列可讀取與更新，均不呼叫模型：

```powershell
python -m assistant --show-companion
python -m assistant --set-companion profile.json --profile-revision 0
python -m assistant --reset-companion --profile-revision 1
```

`--profile-revision` 使用讀取時回傳的版本編號；上述0、1僅為首次操作的例子。JSON檔使用UTF-8，內容是回傳的 `settings` 物件，需有完整六欄，例如：

```json
{"assistant_name":"小禾","user_name":"","tone":"warm","detail":"adaptive","support":"balanced","notes":"先說重點，不用每次喊名字。"}
```

語氣值為 `warm/lively/direct`，長度為 `adaptive/concise/detailed`，互動方式為 `balanced/listen_first/action_first`；日常建議直接用視窗選項。

## 自主目標與下一階段（v0.20）

開啟 `Start.cmd`，在目前對話加入需要的「參考文件」，再按上方「自主目標」。輸入例如「比較兩份方案、計算費用並整理有來源的報告」，保存目標後按「開始／接續自主工作」。模型會依結果自行選擇查找、讀取指定行、查找有效記憶、精確四則計算、必要提問或交付文字成果，每一步都有紀錄。原始文件不變更。

已交付成果後，可選取那個目標，在上方輸入下一項需求，例如「沿用剛才確認的方案，計算12個月費用」，再按「帶入所選成果，建立上方的新目標」。所選階段的成果、問題與使用者補充會固定保存為歷史背景，可先查看，再開始新階段；原目標不改動。按「查看上一階段」可回到原紀錄。一般的「保存新目標」不會自動帶入其他目標。

帶入歷史不等於確認內容正確，也不增加工具權限。新階段使用目前對話已匯入的文件，前後版本不同會明示；舊引用必須重新讀取，移除的來源不會被重新開啟。新要求與本階段補充優先於舊背景。只沿用直接選取的那一階段，不自動複製全部祖先階段、原工具紀錄或記憶摘錄；成果文字本身若包含舊資訊，仍會作為選取的歷史內容帶入。完整階段關係與快照只保存在本機，納入本機備份。

每輪預設6步、可設1–12步，每個目標累計最多32步；用完先保存暫停，按同一按鈕接續。遇到必要問題，在補充欄回答並保存，再接續。可隨時停止；關閉主視窗會先取消自己啟動的自主工作。重開後選同一對話可查看原目標、進度與成果。檔案清單或匯入版本變更時，舊目標暫停，需另建目標以免混用版本。

「成果待確認」表示文字已保存，來源引用存在性也已檢查；它不是內容一定正確或現實工作全部完成的證明。計算提供精確分數值，以及最多40位有效數字的十進位顯示，是否捨入會明示。來源範圍檢查不保證文字真的支持結論。

這是使用者啟動的有限自主流程，目前沒有背景排程、網路搜尋、任意程式執行、原檔修改、訊息發送或自動串接自我改碼。一般聊天仍提供建議；它能看最近三個目標的狀態摘要，工具原文與成果不會自動重播到聊天。完整內容在自主目標視窗。AI 是否有主觀意識仍有爭議，本專案不保證意識或全能；開發方向與後續能力見 [長期路線](docs/ROADMAP.md)。

目標及工具結果存於本機資料庫，工具選取的內容會交給模型處理，不上傳 GitHub；本機備份包含目標與步驟。接續會把先前步驟作為歷史證據傳給模型，包括當時的記憶摘錄；後續修改／刪除記憶不會抹除既有工作紀錄與備份。新一次記憶查找只取目前有效項目。若不希望再使用舊摘錄，請另建目標。

```powershell
python -m assistant --new-goal "比較已匯入的方案並計算費用" --session 對話ID
python -m assistant --new-goal "沿用已確認方案，計算12個月費用" --from-goal 已交付的目標ID --session 對話ID
python -m assistant --run-goal 目標ID --session 對話ID --goal-steps 6
python -m assistant --goal-status 目標ID --session 對話ID
python -m assistant --reply-goal 目標ID --goal-reply "需要補充的資訊" --session 對話ID
```

接續提問支援「第二個呢？」、「請把上面的回答改成表格」等短句，可補取前一題相關的記憶與文件。禮貌用語及全形數字不會阻斷這些已支援句型；明確換話題或「第二個質數是多少」等新問題不會因序數而沿用舊檢索主題。這是有限句型的參考選取，不能保證理解所有省略語，也不會自動執行方案。

長對話會獨立保留較早的最近六則明確更正原文，例如「更正：……」、「不是這個，我是指……」及「Correction: …」，不受一般早期摘錄的兩百則掃描範圍限制。每則最多一千字，附訊息編號及省略標示，可在「本次參考資料 → 早期更正」查看。只辨識開頭的有限句型，不代表完整歷史、已確認事實或已存入長期記憶；當前要求仍優先。需跨對話保存時，請使用記憶指令或記憶視窗。

## 開啟

雙擊 `Start.cmd`。首次會在專案內建立 `.venv`，不需安裝第三方 Python 套件。
需要 Windows、Python 3.12（含 Tk）、Codex CLI 與有效登入及網路。程式、虛擬環境、資料都在專案內；Python 基礎安裝、Codex 執行檔與登入憑證仍沿用系統安裝，因此不是離線或完全可攜式模型。

引擎的回答逾時包含啟動、傳送問題與等待結果；即使子程序沒有讀取問題，「停止」與逾時仍可生效。為避免大段上下文卡在管線寫入，問題會先放在本機暫存輸入，再供引擎讀取；正常完成、取消或失敗後會關閉並移除暫存內容。程序崩潰或強制斷電可能留下暫存檔，與其他本機資料一樣不納入 Git。單次推理輸入與回覆各限 2 MiB，超過、空白、無效編碼或非正常退出都不會被保存成完成答案。

逾時與取消是合作式檢查，不能中斷作業系統正在阻塞的磁碟或程序建立呼叫；終止與清理也需額外時間。無法確認程序已結束時會明確回報，不宣稱完成。程式不自動重送失敗問題，避免重複使用額度；可依錯誤訊息檢查登入、網路與磁碟後自行重試。CLI 的 `--ask` 失敗會回傳非零狀態與簡短說明，不直接顯示堆疊或引擎 stderr 中可能包含的私人內容。

```powershell
python -m assistant --doctor
python -m assistant --ask "幫我把學習 Python 拆成四週計畫"
```

桌面版支援對話紀錄、停止回答、長期記憶新增／編輯／停用／到期日／刪除、對話目標與限制、回答參考快照、回答評分與更正、JSON 匯出。Ctrl+Enter 傳送。

回答逾時、取消或失敗後，狀態會保存在本機，重新開啟對話也能看到。若最後一題沒有完成，且之後沒有其他訊息，可按「重試最後一題」：使用同一筆問題，重新取得目前有效的記憶與已匯入文件，再明確呼叫一次模型，不重複新增問題，也不自動重送。原來失敗的嘗試與新嘗試會分別保留；同一對話同時只允許一個受追蹤的模型回答流程。

重試使用現在的資料，不重播失敗當時的快照：已刪除或停用的記憶、已移除的文件不會從舊快照帶回。若要修改問題，或其後已聊了其他內容，請重新送出問題。升級前沒有回答流程紀錄的舊問題不會被猜測為失敗，需重新送出。

程式意外中斷時，會實際嘗試取得該次本機流程的 SQLite 排他鎖；只有鎖已可取得且仍無完成紀錄，才標記中斷。仍持有鎖時不重送，鎖無法檢查時也不假定已停止；鎖檔存在或經過多久都不是判定依據。本機流程中斷不保證雲端請求已停止，重試可能另計使用額度。這些鎖位於 `data/answer-locks`，不包含對話、不上傳或備份；還原到新資料夾的資料庫有獨立持有權，不會影響原本仍在執行的流程。

回答、參考快照與完成狀態在同一交易中保存；沒有完整保存的答案不標記成功。「查看本次參考 → 回答流程」可查看提問前最近三次模型流程狀態；它不是雲端即時狀態。後續聊天也會收到這些狀態摘要，避免把逾時說成問題不清楚。最後一則訊息是否為本機記憶操作另以不含內容的標記提供，避免誤用較早的模型失敗紀錄。JSON 對話匯出在相關問題上附加 `answer_attempts` 狀態；備份包含流程與原參考快照。

```powershell
python -m assistant --retry-answer --session 對話ID
```

CLI 同樣只重試最後一題，不能同時用 `--file` 匯入新文件；需要時先在桌面調整目前參考資料，或將問題重新送出。
聊天推理目前是建議模式：能分析明確選取的文字文件與提供解法；明確的記憶指令由本機程式直接處理。另可由你在「工作工具」規劃並執行 CSV 篩選、分組加總、平均與排序。聊天不能修改原檔、瀏覽即時網頁或代替你執行任意系統工作。

## 記憶與隱私

對話、記憶、回饋存在 `data/assistant.sqlite3`，不納入 Git。
回答時會將當前問題、最近最多 16 則對話、最多 8 筆相關記憶、目前對話的手動目標與限制，以及最多 6 則早期使用者原文摘錄送給 Codex。可辨識的接續問題會參考先前使用者提問檢索記憶；一般新問題不會擴大記憶檢索。偏好可跨問題使用。這是雲端推理，並非資料完全不離開電腦。
記憶採中英文詞彙比對、全形正規化與 13 類常見中英文／繁簡詞對應，目前不具完整語意檢索或通用繁簡轉換。相關資訊依詞彙稀有度與長度排序，一般偏好最多額外加入兩筆。
管理記憶時，可直接修改舊內容以避免新舊版本並存；取消「啟用」會保留記錄但不供回答使用。到期日以本機日期判斷，當日仍有效、翌日起不選取。沒有日期則永久有效。
停用、過期或刪除後，未來不再選取該筆記憶；已生成回答、近期對話或匯出內容不會追溯刪除。若兩筆有效記憶互相矛盾，助理會被要求指出衝突，仍可能需要你手動編輯確認。
首次升級記憶結構前會在 `data/backups/` 建立 SQLite 一致性備份，保留原有記憶、對話與回饋。備份不會上傳 GitHub。
更正只有在你選擇保存時才變成長期記憶。回饋不會自動訓練模型權重。

也可以直接在聊天輸入完整記憶指令，前面可加「請」或「幫我」：

| 指令 | 結果 |
| --- | --- |
| `記住偏好：先給結論，再說明原因` | 保存跨對話偏好，回報編號 |
| `記住：我的專案代號是青鳥` | 保存事實；另有 `記住事實：`、`記住經驗：` |
| `記住事實（到期 2099-12-31）：臨時專案代號是青鳥` | 指定到期日 |
| `列出記憶` | 查看最新 20 筆與編號，每筆預覽最多 200 字 |
| `查看記憶 #12` | 查看該筆完整內容與狀態 |
| `更正記憶 #12：新的內容` | 只改內容，保留類型、啟用狀態與到期日 |
| `停用記憶 #12`／`啟用記憶 #12` | 改變啟用狀態；過期項目仍不供回答使用 |
| `刪除記憶 #12`／`忘記記憶 #12` | 刪除指定長期記憶，保留既有對話、匯出與備份 |
| `記憶指令` | 查看指令說明 |

一次處理一個指令；冒號後的全文是要保存的原始資料，最多 4000 字，不會執行內含的其他指令。這是明確句型辨識，不是任意自然語言記憶操作。一般聊天、引文與文件不會自動保存；其他表達方式仍需採用上述指令或記憶視窗。完全相同的啟用記憶（含類型與到期日）不重複新增，其他新內容不自動合併或取代舊記憶，請用更正指令。

本機指令不呼叫模型，資料變更與回覆紀錄在同一交易中保存，失敗或提交前取消會完整回復。「查看本次參考」可查看操作狀態、編號與前後內容指紋。指令及其回覆仍留在本機對話、匯出及備份中，但不加入後續模型的最近對話或早期摘錄，避免刪除的內容從操作紀錄再次進入回答。未來提問仍可能將有效、相關的記憶傳給 Codex；一般舊對話中的相同資訊不會追溯移除。

v0.10 起記憶編號遞增並隨備份保留，刪除最高編號後也不重用；升級時以現存最大編號初始化，無法重建升級前已刪除的編號紀錄。還原舊備份會回到該備份的資料與編號狀態；請以目前記憶列表確認編號。

## 長對話與參考來源

「對話目標與限制」可以保存當前目標、限制、已確認決策，每欄最多 2000 字，只套用於這一段對話；請隨需求變更手動更新。這些內容不會自動成為跨對話的長期記憶。

程式會從最近 200 則較早的使用者訊息及最初提問中，依問題關聯與目標／限制／更正用語選取最多 6 則原文摘錄。這是可追溯的摘錄，不是模型自動生成的完整摘要，也不保證保留所有約定；非常重要的要求請寫進對話目標與限制。

近期對話總長上限 24000 字，每則最多 6000 字；記憶每筆最多 1500 字；早期摘錄每則最多 1000 字。長內容保留頭尾並標記中段省略。這是字元預算，不等同精確 token 計費。

「查看本次參考」可查看該回答送出時的資料快照，包含原文訊息編號。快照不代表模型一定採用每一筆內容，也不包含 Codex 平台的內部提示。快照隨本機資料庫保存，不會上傳 GitHub；後續編輯或刪除記憶不會改寫舊快照。升級前的回答沒有快照。

對話推理程序使用 `project_doc_max_bytes=0` 避免將這個專案的開發指引混入一般回答；仍維持唯讀與停用工具。設定依據：[OpenAI 官方設定參考](https://learn.chatgpt.com/docs/config-file/config-reference)。開發工作本身仍遵守專案 AGENTS.md。

## 實際工作工具：CSV 計畫與驗證

在主視窗右上角點「工作工具」，選取 CSV、分組欄與數值欄，再點「建立計畫」。先核對來源路徑、內容指紋、前五筆預覽與處理規則，再按「執行選取計畫」。計畫保存不代表已執行；只有來源、筆數與分組總和核對成功才標記完成。執行及計算完全在本機，不呼叫模型。

例如 `A,2`、`B,4`、`A,3`，結果為 A 共兩筆加總 5、B 一筆加總 4，總計 9。數字使用十進位精確加總，報告數值以字串保存以避免浮點誤差。「匯出已驗證報告」另存 JSON、核對輸出雜湊並保存匯出紀錄；目的檔已存在時拒絕覆寫。JSON 內的文字不會被當成試算表公式執行。

來源仍以 2 MiB 為上限，最多 200 欄、50000 筆、5000 組、4 MiB 結果。CSV 使用逗號與標準雙引號規則，支援 UTF-8／含 BOM 的 UTF-16；不自動猜分隔符。標頭去除前後空白且不能重複，分組值原樣保留，空白分組是一組；完全空白的記錄行忽略，欄內換行保留。數值去除前後空白，最多 60 字元，只接受普通十進位數字，不接受空值、千分位、貨幣符號、NaN、Infinity 或科學記號。錯誤會使整個工作失敗，不會略過資料或當作零。

執行前與計算後重查來源指紋；來源版本不同時需建立新計畫。每個計畫只能執行一次，重跑需另建計畫。可按「停止」，30 秒限制與取消為檔案處理之間的合作式檢查，無法中斷已阻塞的作業系統 I/O。若程序意外結束，保存的 running 只是未完成紀錄，不代表程序仍活著；請建立新計畫重新處理。

詢問工作失敗原因時，聊天會取得已辨識的原因與下一步摘要，例如來源版本變更、數值不合法、逾時或取消，並提醒重新建立及核對計畫。摘要不含原始錯誤路徑或來源數值，只對完全符合已知格式的紀錄給出原因；無法辨識時會請你在工作工具查看本機錯誤，不猜測。資料筆序從第一筆資料算起，不等於含標頭或多行儲存格的檔案行號；歷史失敗也不代表來源目前仍有相同問題。

```powershell
python -m assistant --run-task 任務ID --session 對話ID
python -m assistant --task-status 任務ID --session 對話ID
```

第一個命令回傳任務 ID 與 `session_id`；後續使用這兩個值。CLI 的輸出為 UTF-8。可以加上 `--data-dir` 使用其他本機資料目錄，所有步驟必須使用同一目錄。

也可在選取 CSV 後填「工作需求」，按「用文字規劃」。例如：「只保留 state 完全等於 paid，依 team 加總 amount，按總額由大到小列前兩組。」模型只收到需求與欄位名稱，不收到資料列、原始檔路徑或整份 CSV。產生的計畫會連同原始需求、每步條件與規則顯示；請核對後再按「執行選取計畫」。規劃本身不執行，資料不清楚時會詢問，超出能力時會說明限制。

多步計畫支援最多六個依序全部成立（AND）的條件，再單欄分組、單欄加總與算術平均、依組名／加總／筆數／平均升降冪排序，以及前 1–5000 組或全部。文字條件為完全相等、不相等、包含、開頭；數值條件為等於、不等於、大於、大於等於、小於、小於等於。文字大小寫與空白都保留；數值同樣只接受普通十進位。條件依序執行，先前已被排除的列不再檢查後面欄位；仍要處理的列有不合法數值就整體失敗，不能默默當零。日期開頭篩選只是字串比對，不代表日期解析。

同加總、同筆數或同精確平均時，按組名的字元順序升冪，並非中文筆畫或自然數字排序。報告明確區分來源筆數、符合筆數、排除筆數，保存每個條件的中間筆數；`total` 是所有符合條件的總額，`returned_total` 才是前幾組總額，兩者可不同。如果未列出的組有負值，前幾組總額甚至可大於全部總額。`group_count` 是所有符合分組，`returned_group_count` 是報告所列分組；`selection_limited=true` 表示只選了前幾組。

篩選 `op` 可為 `eq`、`ne`、`contains`、`starts_with`（文字）或 `num_eq`、`num_ne`、`gt`、`gte`、`lt`、`lte`（數值）；`value` 一律是字串。排序 `by` 可為 `group`、`sum`、`count`、`mean`，`direction` 為 `asc` 或 `desc`。不接受任意程式碼、命令、其他來源路徑或額外操作。現階段沒有另指定權重欄的加權平均、中位數、其他平均捨入位數或規則、OR、多欄分組、跨檔合併、日期解析或相對日期、寄信、上傳、排程和自動匯出；模型不能省略不支援部分後假稱整個需求可做。即使規格格式正確，也仍需核對是否符合你的原意。

## 本機備份與還原

點「本機備份與還原 → 建立本機備份」，會在目前資料目錄的 `backups` 中建立 `.paibackup`。備份透過 SQLite 一致性快照保存已提交的資料，包含對話、記憶、回饋、目標、文件副本、回答快照及工作紀錄／結果；不包含程式、原始文件、外部匯出檔、Codex 登入或模型。正在生成且尚未儲存的回答不在該次快照內。可還原 v0.5／v0.6 的備份，開啟時會補上空的工作表；含工作資料的新版備份需用相容新版程式開啟。

「從備份還原到新資料夾」會要求選取備份與存放位置，檢查雜湊、資料庫完整性、關聯及格式後，建立新的 `assistant-restored-日期-識別碼` 資料夾。完成後按「開啟還原後的助理」使用該資料；新視窗標題會顯示資料位置。原視窗與 `Start.cmd` 仍使用原資料，兩份資料不會自動合併。原始文件的路徑可能已失效，但匯入副本仍可分析；重新匯入需原檔仍存在。

```powershell
python -m assistant --backup
python -m assistant --inspect-backup "F:\Backups\assistant.paibackup"
python -m assistant --restore "F:\Backups\assistant.paibackup" --data-dir "F:\AssistantRecovered"
python -m assistant --data-dir "F:\AssistantRecovered"
```

命令列還原目的資料夾必須不存在；不會覆寫任何現有資料目錄。備份／檢查／還原不需登入或呼叫模型。支援目前完整資料庫格式，單一資料庫上限 512 MiB；舊版請先以相容新版開啟完成結構升級，再建立備份。未支援未來格式或舊的遷移用裸 SQLite 備份。

備份未加密，應視為私人資料；Git 忽略並拒絕發布 `.paibackup`。請自行將重要備份複製至其他磁碟，留在 F 槽的備份不能防止 F 槽故障。沒有排程備份、雲端備份或自動刪除舊備份。雜湊可發現損壞，不提供來源身分認證。驗證／還原過程會使用作業系統的本機暫存目錄。

## 更自然的溝通與自我改進

對話會參考已保存的偏好、當前格式要求與前後文，接受更正、調整詳略，並區分「需要傾聽」與「需要解法」。在「管理長期記憶」保存偏好即可跨對話使用；最新明確要求優先。程式辨識的溝通提示只是可能誤判的線索，可在「查看本次參考 → 溝通提示」查看。

開啟頂端「自我改進」，填一個具體改善方向，選取模組，按「開始改進並發布」。預設可改 `assistant/communication.py` 與 `prompts/communication.txt`，另外可選 `assistant/context.py`（脈絡）與 `assistant/retrieval.py`（記憶檢索）。這是實際產生並套用原始碼差異，不只是聊天建議；每次只做一輪，不會在背景無限改碼。

流程：要求乾淨 Git 版本 → 僅複製已追蹤程式 → 模型產生選定檔案的完整變更 → 副本跑全部測試與離線評估 → 再確認原始版本未變 → 套用 → 確認私人庫並發布、核對遠端提交。模型不能透過變更回傳格式修改控制器、測試、發布工具或資料庫。副本是**版本隔離，不是作業系統沙箱**：測試會以你的帳號執行候選 Python 程式。測試通過也不保證所有情境品質提升，重要改善仍需實際對話評讀。

失敗於套用前會保留原程式；發布失敗會清楚標為「已套用但發布未確認」，保留本機修改與紀錄，可修復問題後執行 `Publish.cmd`。停止只在套用前生效；開始套用／發布後會完成該步驟。發布成功後重新啟動助理，讓全部模組載入新版。

```powershell
python -m assistant --improve "更準確辨識使用者要求簡短回答的說法" --edit assistant/communication.py
python -m assistant --rollback-improvement 20261102-180000-1234abcd
```

回復指令中的 ID 請換成實際紀錄。只可自動回復仍為目前最新的已發布自我改進，透過 `git revert` 建立新提交並發布，不刪歷史、不改私人資料；有後續變更時會停止，避免覆蓋其他工作。回復發布失敗時也可重跑 `Publish.cmd`。一般聊天不自動觸發改碼，也不訓練模型權重。

本機 `data/evolution/<ID>/report.json` 保存目標、基底提交、候選檔案雜湊、各項檢查與發布結果；同目錄保留候選程式、模型提案與日誌，不上傳 GitHub。備份工具只備份助理資料庫，不包含這些開發紀錄，需另行保存。若程序異常終止，先確認已無自我改進程序，再移除 `data/evolution/active.lock`；不要在正在改碼時移除。傳給模型的內容是選定原始碼與你輸入的改善方向，不會自動附上私人對話；請將問題改寫成不含私人資料的範例。

詢問是否曾自改程式時，聊天會讀取最多三筆相關流程摘要，先核對本機 Git 提交與檔案雜湊；摘要不包含原始改善目標、錯誤日誌、程式內容或絕對路徑。這能證明歷史改版，不能證明遠端現在的狀態、目前開著的程式已重載，或模型整體變聰明。發布時另外核對選定檔案清單與測試過的內容雜湊，避免同路徑的新改動被混入。

自我改進也可提供「驗收例子」：桌面中輸入一句話並選擇預期辨識的回答長度，或匯入多案例 JSON。流程會先測原版本，再對候選版測完全相同的案例；必須全部符合預期，而且至少改善一個原先失敗的案例，才會套用。若原版已全部通過，會直接回報「目前已滿足案例」，不呼叫模型、不改碼。若沒提供例子，仍可使用原本的回歸測試流程，但不會宣稱本輪新需求已驗收。

也可從「回饋紀錄」選取一筆已填更正的模型回答，直接建立回答長度或接續前文的驗收例子。畫面會顯示原回答、更正與當時溝通提示；下方的問題、近期前文 JSON 和改善描述都可編輯，請先移除不需要的私人資訊，再自行選擇期望的長度提示（簡短／詳細／混合／未指定）。原回答不會自動附給改碼模型。

按「帶入自我改進」只開啟預填視窗，尚不呼叫模型或改碼；可按「查看完整驗收案例」核對實際資料。另按「開始改進並發布」才會將編輯後的描述、案例及選定原始碼傳給 Codex。開始前會重查來源回饋與快照，已變更時需重新選取。改善類型為「回答長度辨識」時，選定 `communication.py`；改選「接續前文檢索」時，選定 `context.py`。後者需明確選擇不沿用前題，或按「從編輯後前文載入可選訊息」並選取一至四則使用者前文；空選取不會被當成不沿用，助理回答不能成為期望檢索文字。修改前文後需重新載入並選取，避免沿用錯誤編號。每則期望前文最多一千字，保留首尾，完整驗收頁會顯示省略標記。這兩種驗收仍不直接評分整篇回答品質；事實錯誤、工具失敗等需另建適合的目標與案例。

沒有具體更正、有幫助的評價、本機記憶操作及舊版無快照回答，不會直接產生改碼例子。近期前文已截斷時也需另填可重現的例子。驗收格式最多 16 則前文，每則及問題最多 4000 字，改善描述最多 2500 字；資料不符限制時會要求調整。這是使用者明確指定的程式驗收，不是自動蒐集所有回饋、訓練權重或自行替使用者決定正確答案。

```powershell
python -m assistant --improve "正確理解回答長度要求中的否定詞，保留原有辨識" --edit assistant/communication.py --acceptance evals/improvement/communication_negation.json
```

驗收檔是 `{"version":1,"cases":[...]}`，最多 40 題、200 KB。支援 `communication`（溝通提示欄位）、`followup`（接續問題所需的前文文字或 null）、`retrieval`（排序後的記憶 ID）；各案例必須對應本輪選定的模組，不接受 Python 表達式或任意命令。溝通範例見 [否定句驗收案例](evals/improvement/communication_negation.json)。輸入案例及預期會交給改碼模型，因此這些是已知需求驗收，不是獨立盲測；也不是模型回答品質分數。

每輪的 `acceptance.json`、`baseline-observations.json`、`candidate-observations.json` 與比較結果保留於本機 `data/evolution/<ID>`。控制器固定預期、核對案例未被改動、在新程序收集實際輸出後自行評分；模型不能透過回傳 `passed=true` 自行判定成功。沒有通過的候選會保留供查看，但不套用。

以下命令另行收集 9 個真實對話案例的回答，保存在本機並逐題依 rubric 評讀，不使用上述程式提示的符合數代替語意評讀：


## 更新到 GitHub 私人庫

雙擊 `Publish.cmd`，或執行：

```powershell
python scripts/publish.py --message "改善問題理解與測試"
```

發布流程會先跑測試與檢索評估，確認 GitHub 儲存庫為 PRIVATE、origin 符合專案，檢查來源路徑與常見憑證特徵，再 commit 和 push。未使用強制推送。失敗會停止；網路問題可修復後重跑。掃描只是基本防護，不能保證識別所有敏感資料，請勿將私人內容放進原始碼或測試案例。
每次完成的開發更新透過此流程發布，沒有背景監看器上傳每一次按鍵或未完成檔案。
